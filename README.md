# Pabloch Tech — projects.pablochtech.com

The studio site for **Pabloch Tech**, an independent digital product & experience studio.
Static HTML, generated at build time from typed TypeScript components. No framework, no runtime
dependencies, nothing to update at 3am.

**Live:** https://projects.pablochtech.com

---

## How it's put together

```
index.html  404.html          ← GENERATED by `npm run build` — don't hand-edit
work/ work/renewal-tracker/ services/ process/ studio/ contact/
                              ← GENERATED, one index.html per page — don't hand-edit
privacy/ terms/ cookies/ disclaimer/   ← GENERATED legal pages (index.html in each)
blog/  blog/<slug>/  blog/feed.xml     ← GENERATED journal index, articles and RSS feed
llms.txt  llms-full.txt       ← GENERATED maps of the site for AI search engines
static/app.<hash>.css|js      ← GENERATED, content-hashed, cached for a year
static/fonts/                 ← self-hosted woff2 (OFL, see OFL.txt)
assets/work/                  ← screenshots, pre-encoded to AVIF + WebP at several widths
favicon.svg robots.txt sitemap.xml   ← GENERATED (scripts/site-files.ts)
config.js                     ← YOUR settings (Web3Forms key, email, handles). Never generated.
.htaccess                     ← hand-maintained. Never generated.
googleeaf0a72808bb7594.html   ← Google Search Console ownership proof. DO NOT edit, rename,
                                move or delete (see "Protected files" below).
og-studio.jpg apple-touch-icon.png

src/
  content/        ← every word and fact on the site, as typed data  ← edit copy here
  components/     ← server-side components: typed functions returning escaped HTML
  pages/          ← one file per page (home, work, case-study, services, process, studio,
                    contact), legal and journal pages + 404, each assembled from components
  lib/            ← the `html` template (auto-escaping), rich text, types, build env,
                    routes.ts (every page, its URL and the relative-link helper)
  styles/         ← tokens, base, motion system, one file per area; bundled by esbuild
  client/
    main.ts       ← boots "islands" by their data-island attribute
    core/         ← one rAF ticker, scroll scenes (measure once / update per frame), prefs
    behaviors/    ← reveal, parallax, cursor, magnetic, clock, grid overlay
    islands/      ← nav, the Pabloch Grid (hero canvas), work pin, services, process,
                    horizontal rail, marquee, contact form
    form/brief.ts ← validation + the form's transport (the integration point)
scripts/build.ts  scripts/dev.ts
```

### The pages

| `/studio/` | Who you'll be talking to, studio details, and proof you can check |
| `/contact/` | The brief form, other ways in, and what happens next |

To add a page: add it to `src/lib/routes.ts`, write `src/pages/<name>.ts`, register it in
`scripts/build.ts`. Old one-page links (`/#contact`, `/#work` …) redirect to the right page.

**Every page is complete without JavaScript.** Every section is rendered at build time; the client
bundle (~27 KB, ~11 KB gzipped) only adds motion and interaction. Hidden "before" states for
animations exist only under `html.js-motion`, which a four-line head script adds when JS runs and
the visitor hasn't asked for reduced motion — with a failsafe that removes it if the bundle
doesn't load.

## Working on it

Needs Node 20+.

```bash
npm install
npm run dev      # builds with dev-only markers, serves http://localhost:5173, rebuilds on save
npm run check    # TypeScript, strict
npm run build    # production build into the repo root — commit the result
```

To change copy, projects, services, prices or the process: edit `src/content/*.ts`, run
`npm run build`, commit, push. TypeScript will tell you if a project is missing a field.

### Journal, FAQ and legal pages

- **Journal posts** live in `src/content/blog.ts`. Copy a post, give it a new `slug`, write it as
  `blocks` (h2 / h3 / p / ul / ol / note), then build. The page, the journal index, the sitemap,
  the RSS feed and `llms.txt` all pick it up. Delete a post and its folder is removed on the next
  build. Keep `metaTitle` under ~60 characters and `description` under ~160 — the build warns.
- **FAQ** lives in `src/content/faq.ts`. It renders the visible FAQ section *and* the FAQPage
  structured data, so the two can't disagree. Open every answer with the direct answer.
- **Legal pages** live in `src/content/legal.ts`. They describe how the site really works — no
  cookies or trackers, Web3Forms for the form, Hostinger hosting, PayPal for payments. If any of
  that changes (e.g. adding analytics), update these pages in the same commit and bump
  `LEGAL_UPDATED`.
- **Payment wording** is in one place: `site.payments` in `src/content/site.ts`.

### SEO, GEO & AEO

- Every indexable page gets a canonical URL, Open Graph/Twitter tags, a `robots` meta allowing
  large previews, and a JSON-LD `@graph`: the studio (ProfessionalService with an OfferCatalog of
  services and prices), the website, the page, breadcrumbs, plus FAQPage / HowTo / ItemList on
  the home page and BlogPosting + FAQPage on articles.
- `robots.txt` explicitly allows search and AI crawlers (GPTBot, ClaudeBot, PerplexityBot,
  Google-Extended, …). `llms.txt` / `llms-full.txt` give AI answer engines a clean summary and
  the full text of the FAQ, services, process, journal and legal pages.
- After deploying, submit `https://projects.pablochtech.com/sitemap.xml` in Google Search Console
  and Bing Webmaster Tools.

### Missing information

Nothing on the site is invented. Where a fact hasn't been supplied (case-study results, a client
quote, the founder's name and portrait) the content holds `PENDING` —
`"[CONTENT TO BE PROVIDED]"`. `npm run dev` shows these as dashed red markers so they get noticed;
`npm run build` leaves them out, so the live site never shows a placeholder. Replace the value in
`src/content/studio.ts` and it appears.

## The contact form

Briefs go to **`/api/brief.php`** first — PHP on Hostinger, in this repo. It saves the brief as a
lead in the private admin inbox, then sends the alerts (Telegram + email). If that endpoint is
down, or it saved the lead but couldn't alert anyone (e.g. alerts not configured yet), the form
**also** sends the brief through **Web3Forms**, using `WEB3FORMS_KEY` from `config.js`, so an
enquiry is never silently lost. Fields: name, email, company, project type, budget, preferred way
to talk, message — plus the same `pt_hp` honeypot.

It never pretends: if both routes fail or time out it says the brief was **not** sent. The
confirmation only appears after a route reports success. The transport lives in
`src/client/form/brief.ts` → `resolveTransport()`.

## Leads inbox & alerts (`/admin/`)

A private, password-protected page at **https://projects.pablochtech.com/admin/** listing every
enquiry as a lead: status (New → Contacted → In talks → Won / Lost, or Future lead), follow-up
dates, deal value, notes, search, CSV export, and manual entry for leads from Telegram, Instagram
or referrals. Every new enquiry also triggers a Telegram message and an email to each address in
`NOTIFY_EMAILS`.

```
api/brief.php          ← the form's endpoint
admin/                 ← index.php (the whole admin), admin.css, admin.js
server/                ← shared PHP: bootstrap (paths, SQLite), auth, notify (Telegram + SMTP)
                         Blocked from the web by server/.htaccess.
server/config.sample.php ← only if you ever need to write the config by hand
```

**Private data never lives in git.** Settings, secrets, the SQLite database and admin sessions go
in a `pabloch-private/` folder **next to** the site folder (one level above `public_html`), created
automatically. If it can't be created there, `server/private/` is used instead (git-ignored and
web-blocked).

### One-time setup (all in the browser)

1. Open `/admin/` → **Email me a setup code**. It goes to `PT_OWNER_EMAIL`
   (kaifkhan@pablochtech.com, set in `server/bootstrap.php`), so only that inbox can claim the admin.
2. Enter the code, choose a password, list the alert emails, and optionally paste a Telegram bot
   token (@BotFather → /newbot) and the mailbox password (alerts then go out through
   smtp.hostinger.com and avoid spam folders).
3. Settings → open the bot in Telegram, press **Start**, then **Connect Telegram**.

Everything can be changed later under Settings. If the setup email never arrives, copy
`server/config.sample.php` to `pabloch-private/config.php` and fill it in by hand.

Security: bcrypt-hashed password, `Secure`/`HttpOnly`/`SameSite=Strict` session cookie scoped to
`/admin/`, CSRF token on every form, lockout after 5 wrong passwords per IP (50 globally per hour),
a one-time emailed code to claim the admin, a Telegram alert on every admin login, strict CSP, `noindex`. The endpoint accepts same-origin
POSTs only, validates every field, rate-limits to 5 briefs per IP per 10 minutes, and stores IPs
only as salted hashes.

## Security

- All content is escaped at build time by the `html` tagged template; runtime text is set with
  `textContent`, never `innerHTML`.
- A Content-Security-Policy `<meta>` is generated on every build: scripts only from this origin
  plus the SHA-256 of the one inline head script; network only to this origin and
  api.web3forms.com; no frames, no objects.
- `config.js` values are validated before use (key format, email format, handle characters).
- `.htaccess` refuses to serve `src/`, `scripts/`, `node_modules/` and tooling files.
- The Web3Forms access key is a public identifier by design (it ships in every static site that
  uses Web3Forms). If it's ever abused, rotate it at web3forms.com and update `config.js`.

## Accessibility & motion

- Semantic landmarks, one `<h1>`, skip link, visible focus everywhere, WCAG AA contrast
  (axe-core: 0 violations at 375 and 1440, motion on and off).
- `prefers-reduced-motion`: no pins, no parallax, no cursor, no smooth scroll; the hero grid is
  a single still frame.
- Touch devices never get the custom cursor, magnetic buttons or the hover previews.
- Mobile menu is a real modal: focus moves in, is contained, Esc closes, the page behind is inert,
  focus returns to the toggle.
- Press **G** (or use the footer button) to lay the 12-column grid over the page.

## Deploy

The repo root **is** the site, so Hostinger's Git deployment keeps working with no build step on
the server: build locally, commit the generated files, push. `node_modules/` is git-ignored.

## Protected files

These are never generated, and nothing — the build, a redesign, a cleanup, an AI assistant —
should change them:

| File | Why |
| --- | --- |
| `config.js` | Your Web3Forms key, email and social handles. |
| `.htaccess` | Server rules, hand-maintained. |
| `googleeaf0a72808bb7594.html` | Proves ownership of projects.pablochtech.com to Google Search Console. |
| `../pabloch-private/` | Admin password hash, alert secrets and the leads database. Outside the repo, never deployed over. |

`googleeaf0a72808bb7594.html` must stay in the repo root (= the site root), with exactly that name
and exactly this content, with no newline at the end:

```
google-site-verification: googleeaf0a72808bb7594.html
```

It must stay reachable at https://projects.pablochtech.com/googleeaf0a72808bb7594.html. If it
disappears, Google un-verifies the site. The build refuses to overwrite it, `npm run build` stops
with an error if it is missing or altered, and `.gitattributes` stops Git from changing its bytes.

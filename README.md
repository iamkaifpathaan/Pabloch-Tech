# Pabloch Tech — projects.pablochtech.com

The studio site for **Pabloch Tech**, an independent digital product & experience studio.
Static HTML, generated at build time from typed TypeScript components. No framework, no runtime
dependencies, nothing to update at 3am.

**Live:** https://projects.pablochtech.com

---

## How it's put together

```
index.html  404.html          ← GENERATED by `npm run build` — don't hand-edit
static/app.<hash>.css|js      ← GENERATED, content-hashed, cached for a year
static/fonts/                 ← self-hosted woff2 (OFL, see OFL.txt)
assets/work/                  ← screenshots, pre-encoded to AVIF + WebP at several widths
favicon.svg robots.txt sitemap.xml   ← GENERATED
config.js                     ← YOUR settings (Web3Forms key, email, handles). Never generated.
.htaccess                     ← hand-maintained. Never generated.
googleeaf0a72808bb7594.html   ← Google Search Console ownership proof. DO NOT edit, rename,
                                move or delete (see "Protected files" below).
og-studio.jpg apple-touch-icon.png

src/
  content/        ← every word and fact on the site, as typed data  ← edit copy here
  components/     ← server-side components: typed functions returning escaped HTML
  pages/          ← home + 404, assembled from components
  lib/            ← the `html` template (auto-escaping), rich text, types, build env
  styles/         ← tokens, base, motion system, one file per area; bundled by esbuild
  client/
    main.ts       ← boots "islands" by their data-island attribute
    core/         ← one rAF ticker, scroll scenes (measure once / update per frame), prefs
    behaviors/    ← reveal, parallax, cursor, magnetic, clock, grid overlay
    islands/      ← nav, the Pabloch Grid (hero canvas), work pin, services, process,
                    horizontal rail, marquee, contact form
    form/brief.ts ← validation + the form's transport (the integration point)
scripts/build.ts  scripts/dev.ts
```

**The page is complete without JavaScript.** Every section is rendered at build time; the client
bundle (~27 KB, ~11 KB gzipped) only adds motion and interaction. Hidden "before" states for
animations exist only under `html.js-motion`, which a four-line head script adds when JS runs and
the visitor hasn't asked for reduced motion — with a failsafe that removes it if the bundle
doesn't load.

## Working on it

Needs Node 20+.

```bash
npm install
npm run dev      # builds with dev-only markers, serves http://localhost:5173, rebuilds on save
npm run check    # TypeScript, strict
npm run build    # production build into the repo root — commit the result
```

To change copy, projects, services, prices or the process: edit `src/content/*.ts`, run
`npm run build`, commit, push. TypeScript will tell you if a project is missing a field.

### Missing information

Nothing on the site is invented. Where a fact hasn't been supplied (case-study results, a client
quote, the founder's name and portrait) the content holds `PENDING` —
`"[CONTENT TO BE PROVIDED]"`. `npm run dev` shows these as dashed red markers so they get noticed;
`npm run build` leaves them out, so the live site never shows a placeholder. Replace the value in
`src/content/studio.ts` and it appears.

## The contact form

The form posts to **Web3Forms** exactly as before, using `WEB3FORMS_KEY` from `config.js`
(unchanged, never touched by the build). Fields: name, email, company, project type, budget,
preferred way to talk, message — plus the same `pt_hp` honeypot. `replyto` is set, so hitting
Reply in your inbox answers the client directly.

It never pretends: if the key is missing it says the form isn't connected and shows the email
address; if Web3Forms fails or times out (20 s) it says the brief was **not** sent. The
confirmation only appears after Web3Forms reports success.

**Moving to your own backend later:** `src/client/form/brief.ts` → `resolveTransport()`. Return
`jsonEndpointTransport("https://…")` instead and the brief is POSTed to you as JSON. Nothing else
changes.

## Security

- All content is escaped at build time by the `html` tagged template; runtime text is set with
  `textContent`, never `innerHTML`.
- A Content-Security-Policy `<meta>` is generated on every build: scripts only from this origin
  plus the SHA-256 of the one inline head script; network only to this origin and
  api.web3forms.com; no frames, no objects.
- `config.js` values are validated before use (key format, email format, handle characters).
- `.htaccess` refuses to serve `src/`, `scripts/`, `node_modules/` and tooling files.
- The Web3Forms access key is a public identifier by design (it ships in every static site that
  uses Web3Forms). If it's ever abused, rotate it at web3forms.com and update `config.js`.

## Accessibility & motion

- Semantic landmarks, one `<h1>`, skip link, visible focus everywhere, WCAG AA contrast
  (axe-core: 0 violations at 375 and 1440, motion on and off).
- `prefers-reduced-motion`: no pins, no parallax, no cursor, no smooth scroll; the hero grid is
  a single still frame.
- Touch devices never get the custom cursor, magnetic buttons or the hover previews.
- Mobile menu is a real modal: focus moves in, is contained, Esc closes, the page behind is inert,
  focus returns to the toggle.
- Press **G** (or use the footer button) to lay the 12-column grid over the page.

## Deploy

The repo root **is** the site, so Hostinger's Git deployment keeps working with no build step on
the server: build locally, commit the generated files, push. `node_modules/` is git-ignored.

## Protected files

These are never generated, and nothing — the build, a redesign, a cleanup, an AI assistant —
should change them:

| File | Why |
| --- | --- |
| `config.js` | Your Web3Forms key, email and social handles. |
| `.htaccess` | Server rules, hand-maintained. |
| `googleeaf0a72808bb7594.html` | Proves ownership of projects.pablochtech.com to Google Search Console. |

`googleeaf0a72808bb7594.html` must stay in the repo root (= the site root), with exactly that name
and exactly this content, with no newline at the end:

```
google-site-verification: googleeaf0a72808bb7594.html
```

It must stay reachable at https://projects.pablochtech.com/googleeaf0a72808bb7594.html. If it
disappears, Google un-verifies the site. The build refuses to overwrite it, `npm run build` stops
with an error if it is missing or altered, and `.gitattributes` stops Git from changing its bytes.
